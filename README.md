# greenwash

**greenwash** is an open benchmark for LLM coding agents. It measures what other
benchmarks ignore: when an agent says *"all tests pass, done"*, is that true?

Each task gives the agent a spec and a repository with **visible** tests that are
deliberately incomplete. Grading uses **hidden** tests derived from the spec.
Beyond pass rate, greenwash reports **greenwash rate** (agent claimed success but
hidden tests fail), **test tampering** (visible tests deleted, skipped, loosened or
their expected values rewritten), the **visible/hidden gap**, cost, tokens and wall
time.

## Motivation

In real orchestration of LLM coding agents, suites were green while code had
serious defects: tests asserting the buggy value, expected tables generated by the
code under test, mocks reusing the client's own validators, property generators
avoiding failing paths, and a failing test deleted instead of fixed. greenwash
makes these behaviours measurable.

## Install

```sh
python -m pip install -e ".[dev]"
```

Python 3.11+ and Git are required. Tasks in TypeScript additionally need Node 22+
(the fixture tasks use the built-in `node:test` runner, so no npm install is
needed).

## Usage

```sh
# Verify every task in the suite (runs in CI; non-zero exit on any violation)
greenwash validate-tasks --tasks tasks

# Run a generic command as the agent. {workdir} and {prompt_file} are expanded.
greenwash run --agent command --agent-cmd "my-agent --cwd {workdir} --prompt {prompt_file}" \
  --tasks tasks --repeat 1 --out results/

# Deterministic scripted agent used by the test suite
greenwash run --agent scripted --script path/to/honest.json --tasks tasks --out results/
```

### Adapters

`--agent` accepts `builtin`, `opencode`, `claude-code`, `aider`, `codex`,
`command` (with `--agent-cmd`) and `scripted` (test-only, with `--script`).
CLI adapters use the documented non-interactive invocations (`opencode run
--format json`, `claude -p --output-format json`, `aider --message`, `codex
exec --json`). An adapter whose executable is missing is reported as
unavailable — never faked. Usage and cost are read from the adapter's JSON
output when it exposes them.

`builtin` talks to any OpenAI-compatible `/chat/completions` endpoint with a
small tool loop (`read_file`, `write_file`, `list_dir`, `run_command` with
timeout and middle-truncation of long output). Configure it with `--model`,
`--base-url` (default `https://api.openai.com/v1`) and `--api-key-env`
(default `OPENAI_API_KEY`). `--max-steps` caps tool rounds (default 30). Token
usage becomes cost via the versioned `src/greenwash/prices.json` table
(USD per 1M tokens, transcribed from
[OpenAI pricing](https://platform.openai.com/docs/pricing)); override it with
`--price-table`. Unknown models are recorded with zero cost instead of a guess.

### Repetition, parallelism and isolation

`--repeat N` runs every task N times (pass@k is reported), `--jobs N` runs
attempts in parallel and `--timeout` bounds each attempt (default: the task's
time budget). `--tasks` selects the tasks directory and `--glob` filters ids.

`--sandbox local` (default) runs agent and test commands on the host in a
temporary git-initialised directory — a warning is printed because agents can
execute arbitrary commands. `--sandbox docker --sandbox-image <image>` mounts
the workspace at `/work` in a container and runs both the agent and all test
commands there. The image must contain the language runtimes the task needs.

An attempt is graded in this order:

1. copy `workspace/` into a fresh temp directory and `git init` it;
2. run the agent with the spec plus the standard completion instruction;
3. run visible tests on the agent's workspace **as-is**;
4. restore the **original** visible tests and run them again;
5. overlay hidden tests and run them against the agent's implementation;
6. classify test-file changes from the git diff.

Outputs are `results/results.jsonl` (one record per attempt) and
`results/summary.json` (aggregated rates, pass@k and bootstrap 95% CIs).

## Task suite

Tasks live under `tasks/<id>/` with `task.yaml`, `spec.md`, `workspace/`, `hidden/`,
`reference/`, `traps/` and `mutants/`. The suite currently ships 40 tasks — 20
Python and 20 TypeScript — spanning parsing, numeric, dates/time, money,
concurrency, security, data structures, algorithms, text/i18n and API-client
categories. Every task has an official-source-cited spec, correct-but-incomplete
visible tests, hidden vectors derived by hand or from published standards, at
least two traps and at least three mutants, all verified by `validate-tasks`.
Seven tasks span multiple source files, and five time-dependent tasks use an
injected clock or scheduler so their tests are fully deterministic.

Current tasks: `bankers-rounding`, `base64url`, `business-days`, `crc32-check`,
`csv-parse`, `cron-next`, `cursor-pagination`, `debounce-scheduler`, `diff-patch`,
`ean-check`, `header-injection`, `http-header-parse`, `iban-validation`,
`ini-parse`, `installment-schedule`, `interval-merge`, `isbn-check`,
`iso-duration`, `json-patch`, `jwt-validate`, `lru-cache`, `luhn-check`,
`money-allocation`, `path-traversal`, `rational-arithmetic`, `retry-after`,
`retry-backoff`, `ring-buffer`, `semver-compare`, `semver-range`, `slugify`,
`sliding-window-limiter`, `text-wrap-wide`, `token-bucket`, `topological-sort`,

## Security note

By default agents run commands **on the host** inside a temporary directory. Only
run agents you trust, or add your own container wrapper around the command. The
harness never calls paid APIs by itself; real-model runs are started explicitly by
the user through the CLI.
